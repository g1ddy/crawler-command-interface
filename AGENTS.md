## Durable Invariants

Always preserve the following invariants:

1. **Deterministic Point-in-Time Replay**: Selecting a sequence must reconstruct the same HUD state without mutating historical sequence states.
2. **Immutable History, Live-Endpoint Mutations**: Historical views remain interactive, but resulting mutations append at the live endpoint rather than rewriting history.
3. **Authoritative Raw Evidence**: Story evidence is authored only in `data/raw/floors/`. `data/floors/*.json` and `data/compiled-timeline.json` are generated with `npm run generate:fixture` rather than hand-edited.
4. **Stable Runtime Wrapper**: `app/domain/fixtures/compiled-timeline.ts` is the Worker-safe TypeScript wrapper around generated timeline JSON; it is not generated by the fixture-sync command.
5. **Shared Runtime Portability**: The shared TypeScript application/domain runtime must work in both deployment targets and remain safe to import/render through the more restrictive ChatGPT Live App Worker path. Importing Ajv-dependent code is allowed only when import/render does not execute schema compilation or other Worker-incompatible behavior.
6. **No Evidence Fallback Leakage**: Missing or partial observations must not be inferred from unrelated evidence or silently replaced with later live state. Preserve partial readings as authored.
7. **Thin Host Adapters**: ChatGPT-specific identity/Worker behavior and GitHub Pages static-host behavior belong at their documented adapter boundaries rather than in divergent copies of the shared application.
8. **Generated Visual Documentation and Architecture Evidence**: `docs/images/screenshot-*.png`, `.maritime/*`, and `docs/images/dependency-graph.svg` are generated, tracked canonical repository assets. Do not hand-edit or retouch them. Verification jobs run automatically as read-only checks without writing back to the active PR branch. Screenshot and Maritime updates are promoted together by the single approval-gated `publish` job in `publish-artifacts.yml`, protected by the `artifact-finalization` environment. Keep generated commit messages free of workflow-skip directives so a rebase or squash merge cannot suppress required `push` workflows on `main`; GitHub may surface follow-on PR workflows in an approval-required state after the bot update, and those recursive runs are not part of artifact finalization.

## Narrow Verification Commands

When iterating on changes:

```bash
npm run generate:fixture
npm run test:unit
npm run build:live
npm run build:pages
```

When changing documented UI states or screenshot-generation code, also regenerate the canonical screenshots:

```bash
npm run test:screenshots
```

Before requesting review or submitting code, execute the full verification suite:

```bash
npm run verify
```

`npm run verify` runs fixture generation, linting, unit tests, both deployment builds, rendered preview tests, and artifact contract checks. Documentation screenshot generation and Maritime architecture verification run as read-only verification jobs (`verify-screenshots` and `verify-maritime` in `publish-artifacts.yml`). They upload generated artifacts for inspection without mutating the PR branch head. Maintainers promote both artifact families together using the approval-gated `publish` job (`artifact-finalization` environment), which verifies head SHA freshness before creating a single combined generated-only commit.
